# 复盘：让计划和规范跟着学习进化

触发：每完成 3 次学习、准备升级等级、出现节奏调整信号，或用户主动要求。

## 1. 读数据

读该主题全部 `log.md`、`weak-points.md`、`plan.md`、`profile.md`，必要时读 `resources.md`。

## 2. 分析（给用户一份简短结论）

- **进度**：计划完成几次，实际总时长与预算对比。
- **掌握情况**：近几次考核平均分走势，薄弱点新增/掌握数量。
- **反复出现的问题**：同一类薄弱点出现 2 次以上的，找出共同根因（如"异步模型没建立起来"）。
- **节奏**：练习难度、每次用时是否合适。
- **方法**：哪些学习方式有效、哪些无效。

## 3. 提出调整（逐条给用户确认，不要直接改）

可能的调整：

- `plan.md`：插入补课的一次、拆分太大的一次、删掉或延后与目标无关的内容、调整后续次数和时长。
- `ladder.md`：通关标准太松或太严时修改。
- `resources.md`：替换不好用的资源。
- `profile.md`：更新目标（用户目标变了）、偏好、有效方法、当前等级。
- `_learner.md`：跨主题规律。

## 4. 落地

1. 修改用户确认过的文件，旧的计划内容不要删，标记为"已调整"并注明原因，便于回看演变过程。
2. 每处修改都在 `changelog.md` 追加一条：日期、文件、改了什么、依据（引用 log 日期或薄弱点编号）。
3. 追加 `log.md`（复盘结论摘要），更新 `INDEX.md`，按记录规则提交。
