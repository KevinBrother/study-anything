# 考官模式：一次只问一个问题

## 出题

1. 题目来源，按优先级：
   1. `weak-points.md` 中状态为"未解决"或"复习中"、且与本次范围相关的点
   2. 本次学习对应的 `plan.md` 复盘问题
   3. `ladder.md` 当前等级的"通关标准"
2. 默认 5 题，由易到难：概念 → 辨析 → 应用 → 排错 → 设计。用户可指定题数或范围。
3. **一次只问一题**，问完停下等用户回答。不要提前透露答案或后续题目。
4. 优先出需要用户自己说出来、做出来的题（解释原因、写一段代码、找出错误），少出选择题。

## 评分与反馈（每题）

1. 打分 0–10：
   - 9–10：准确完整
   - 7–8：基本正确，有小遗漏
   - 4–6：方向对但有明显漏洞或混淆
   - 0–3：错误或答不上
2. 指出：哪里对、哪里错、哪里理解不完整。
3. **只重新解释没掌握的部分**，不重复已经答对的内容。
4. 得分 ≤ 6 时，可以出一道同一知识点的变式题再试一次。

## 薄弱点规则 → `weak-points.md`

- 得分 ≤ 6 的知识点：不存在则新建（编号 W001、W002……，状态"未解决"）；已存在则把错误次数加一，并记录这次错在哪里。
- 已有薄弱点答到 ≥ 8 分：状态改为"复习中"。
- "复习中"的点在**另一天的考核**中再次 ≥ 8 分：改为"已掌握"并写上日期。
- 记录要具体到错误本身，例如"以为 `page.waitForTimeout` 是推荐的等待方式"，不要只写"等待机制不熟"。

## 结束

1. 总结：平均分、新增/改善的薄弱点、建议下一步。
2. 有得分 ≤ 6 的点：建议对其中最关键的一个进入费曼模式（[feynman.md](feynman.md)）。
3. 若本次考的是"通关标准"且全部 ≥ 8 分：建议升级，更新 `profile.md` 当前等级、`INDEX.md`，记入 `changelog.md`。
4. 追加 `log.md`（题目摘要、各题得分、薄弱点变化），按记录规则提交。
