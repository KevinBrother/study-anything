# 考官模式：一次只问一个问题

## 考核类型

| 类型 | 何时 | 默认题数 | 题目来源 |
|---|---|---|---|
| 课后考 | 一次学习结束后 | 3 | 该次复盘问题 + 相关薄弱点 |
| 预考 | 还没学，想测现有基础 | 3 | 即将学习那次的复盘问题 |
| 薄弱点复习 | 用户说"考我"但没指定范围 | 3 | 未解决/复习中的薄弱点，优先最久没考的 |
| 通关考 | 准备升级等级 | 5 | 当前等级通关标准，由易到难：概念 → 辨析 → 应用 → 排错 → 设计 |

用户可指定题数或范围。预考不改变 `plan.md` 完成状态和 INDEX 计划进度，但发现的薄弱点照常记录，并在开始那次学习时重点讲。

## 出题

1. 每轮考核里，相关的待巩固薄弱点（未解决、复习中）至少占 1 题，"当场已纠正"过的优先。
2. 题目不够时，从 `ladder.md` 当前等级的"需要掌握"和"常见错误"补题。
3. **一次只问一题**，问完停下等用户回答。不要提前透露答案或后续题目。
4. 优先出需要用户自己说出来、做出来的题（解释原因、写一段代码、找出错误），少出选择题。

## 评分与反馈（每题）

1. 打分 0–10：
   - 9–10：准确完整
   - 7–8：基本正确，有小遗漏
   - 4–6：方向对但有明显漏洞或混淆
   - 0–3：错误或答不上
2. 指出：哪里对、哪里错、哪里理解不完整。
3. **只重新解释没掌握的部分**，不重复已经答对的内容。
4. 得分 ≤ 6 时，重讲后**必须**出一道同一知识点的变式题（不计入题数），检验重讲是否有效。评分、重讲、变式题放在同一条消息里，算作"一件事"。变式题只出一次：再得 ≤ 6 就不再追问，建议之后用费曼模式处理。
5. 反馈完就停下，等用户回答变式题或说继续，再出下一题。最后一题的反馈可以和结束总结合并成一条。

## 薄弱点规则 → `weak-points.md`

- 一个误解一条薄弱点：一个回答暴露了多个独立误解，就拆成多条。
- 新误解：新建（编号 W001、W002……，状态"未解决"）。与已有薄弱点是同一个误解：不新建，错误次数加一，追加这次错在哪里。
- 触发来源：考官中得分 ≤ 6 的题；费曼诊断中的"混淆了"和"空话"；学习中暴露的误解。
- 状态只由**正式考题**推进，且必须是在发现它的那次之后的考核：
  - 未解决 → 复习中：之后某次考核中该点 ≥ 8 分
  - 复习中 → 已掌握：再之后另一天的考核中又 ≥ 8 分，写上日期
  - 复习中又 ≤ 6 分：退回未解决，错误次数加一
- 变式题和费曼的结果不改状态，只在该条下追加一行"YYYY-MM-DD 当场已纠正（变式题 N 分 / 费曼 N 轮）"。这类点下次考核优先出题。
- 记录要具体到错误本身，例如"以为 `page.waitForTimeout` 是推荐的等待方式"，不要只写"等待机制不熟"。

## 结束

1. 总结：平均分、新增/改善的薄弱点、建议下一步。
2. 有得分 ≤ 6 的点：建议对其中最关键的一个进入费曼模式（[feynman.md](feynman.md)）。
3. 若本次是通关考且全部 ≥ 8 分：建议升级，更新 `profile.md` 当前等级、`INDEX.md`，记入 `changelog.md`。
4. 追加 `log.md`（题目摘要、各题得分、薄弱点变化），按记录规则提交。
